# 2. Что такое CRUD

Когда фронтенд работает с сервером, он не только **получает** данные, но и **изменяет** их.

Для этого существует 4 основные операции:

- **C — Create** → создать
    
- **R — Read** → получить
    
- **U — Update** → обновить
    
- **D — Delete** → удалить
    

---

## Связь CRUD и HTTP-методов

- **Create** → `POST`
    
- **Read** → `GET`
    
- **Update** → `PUT` или `PATCH`
    
- **Delete** → `DELETE`
    

---

## Простое объяснение 

- `GET` → “дай данные”
    
- `POST` → “создай новый объект”
    
- `PUT` → “полностью замени объект”
    
- `PATCH` → “измени только часть объекта”
    
- `DELETE` → “удали объект”
    

---

# 4. POST — создание данных

## Что делает POST

`POST` нужен, когда мы хотим **создать новый объект**.

Например:

- создать пост
    
- создать пользователя
    
- отправить форму
    
- создать комментарий
    

---

## Синтаксис

```js
axios.post(url, body)
```

- `url` — адрес API
    
- `body` — объект с данными, которые отправляем
    

---

## Пример: создаём новый пост

```jsx
import axios from "axios";

async function createPost() {
  try {
    const response = await axios.post(
      "https://jsonplaceholder.typicode.com/posts",
      {
        title: "Новый пост",
        body: "Текст поста",
        userId: 1,
      }
    );

    console.log("Созданный пост:", response.data);
  } catch (error) {
    console.log("Ошибка при создании:", error);
  }
}

createPost();
```

---

## Что обычно приходит в ответ

После `POST` сервер часто возвращает:

- созданный объект
    
- новый `id`
    
- статус `201 Created`
    

Пример ответа:

```json
{
  "title": "Новый пост",
  "body": "Текст поста",
  "userId": 1,
  "id": 101
}
```

---

# 5. PUT — полное обновление

## Что делает PUT

`PUT` обычно используется, когда нужно **полностью заменить объект**.

То есть мы отправляем **всю новую версию объекта**.

---

## Синтаксис

```js
axios.put(url, body)
```

---

## Пример: полностью обновляем пост

```jsx
import axios from "axios";

async function updatePost() {
  try {
    const response = await axios.put(
      "https://jsonplaceholder.typicode.com/posts/1",
      {
        id: 1,
        title: "Обновлённый заголовок",
        body: "Полностью новый текст",
        userId: 1,
      }
    );

    console.log("Обновлённый пост:", response.data);
  } catch (error) {
    console.log("Ошибка при обновлении:", error);
  }
}

updatePost();
```

---

## Как объяснить?

`PUT` =

> “Возьми старый объект и замени его новой полной версией”

---

# 6. PATCH — частичное обновление

## Что делает PATCH

`PATCH` нужен, когда мы хотим **изменить только некоторые поля**, а не весь объект.

---

## Синтаксис

```js
axios.patch(url, body)
```

---

## Пример: меняем только заголовок поста

```jsx
import axios from "axios";

async function patchPost() {
  try {
    const response = await axios.patch(
      "https://jsonplaceholder.typicode.com/posts/1",
      {
        title: "Изменили только title",
      }
    );

    console.log("Частично обновлённый пост:", response.data);
  } catch (error) {
    console.log("Ошибка при PATCH:", error);
  }
}

patchPost();
```

---

## Главное отличие PUT и PATCH

### `PUT`

- отправляем **весь объект**
    
- логика: **полностью заменить**
    

### `PATCH`

- отправляем **только изменённые поля**
    
- логика: **точечно изменить**
    

---

## Очень удобная фраза 

- `PUT` → “перезаписать объект”
    
- `PATCH` → “подправить объект”
    

---

# 7. DELETE — удаление данных

## Что делает DELETE

`DELETE` используется, когда нужно **удалить объект**.

---

## Синтаксис

```js
axios.delete(url)
```

---

## Пример: удаляем пост

```jsx
import axios from "axios";

async function deletePost() {
  try {
    const response = await axios.delete(
      "https://jsonplaceholder.typicode.com/posts/1"
    );

    console.log("Статус:", response.status);
    console.log("Ответ:", response.data);
  } catch (error) {
    console.log("Ошибка при удалении:", error);
  }
}

deletePost();
```

---

## Что важно сказать

После `DELETE`:

- иногда сервер возвращает **пустой ответ**
    
- иногда возвращает только статус
    
- часто статус — `200` или `204`

# 9. Как фронтендер получает API от backend-разработчика

Когда фронтенд начинает работать с реальным проектом, бекендер обычно передаёт:

---

## 1. Base URL

Это главный адрес API:

```txt
https://api.myproject.com
```

---

## 2. Endpoints

Это конкретные маршруты:

```txt
GET /users
GET /users/1
POST /users
PUT /users/1
PATCH /users/1
DELETE /users/1
```

---

## 3. Формат body (что отправлять)

Например, для создания пользователя:

```json
{
  "name": "Alex",
  "email": "alex@mail.com"
}
```

---

## 4. Headers

Например:

```txt
Content-Type: application/json
Authorization: Bearer token
```

---

## 5. Что придёт в ответ

Например:

```json
{
  "id": 12,
  "name": "Alex",
  "email": "alex@mail.com"
}
```

---

## 6. HTTP-статусы

Например:

- `200 OK` — успешно
    
- `201 Created` — создано
    
- `204 No Content` — удалено
    
- `400 Bad Request` — ошибка в данных
    
- `401 Unauthorized` — нет доступа
    
- `404 Not Found` — не найдено
    

---

# 10. Как объяснить, что такое endpoint

**Endpoint** — это конкретный адрес внутри API, который делает определённое действие.

Пример:

- `/posts` → список постов
    
- `/posts/1` → один пост
    
- `/posts/1/comments` → комментарии поста
    

---

## Простая формула

- **Base URL** = дом API
    
- **Endpoint** = конкретный маршрут
    

---

## Пример

```txt
https://jsonplaceholder.typicode.com/posts/1
```

Здесь:

- `https://jsonplaceholder.typicode.com` → Base URL
    
- `/posts/1` → Endpoint

# 11. Что такое body запроса

Когда мы делаем `POST`, `PUT` или `PATCH`, мы часто отправляем **body**.

**Body** — это данные, которые мы отправляем на сервер.

---

## Пример body

```js
{
  title: "Новый пост",
  body: "Текст поста",
  userId: 1
}
```

---

## Когда body обычно нужен

- `POST` → да
    
- `PUT` → да
    
- `PATCH` → да
    
- `GET` → обычно нет
    
- `DELETE` → обычно нет

# 12. Что такое Postman

## Postman — это инструмент для тестирования API

Простыми словами:

> Postman позволяет отправлять запросы вручную, без React и без кода интерфейса.

---

## Зачем он нужен фронтендеру

Перед тем как писать код, удобно:

- проверить, работает ли API
    
- увидеть, какие данные реально приходят
    
- проверить структуру JSON
    
- проверить, что нужно отправлять в body
    
- понять, проблема в API или в коде фронтенда
    

---

## Очень важная мысль

### Сначала:

**проверяем запрос в Postman**

### Потом:

**пишем тот же запрос в axios**

# 19. Что такое useQuery

`useQuery` — это хук для **получения данных**.

Если сказать совсем просто:

> `axios` делает запрос  
> `useQuery` помогает удобно управлять этим запросом внутри React

---

## Пример идеи

Раньше мы пишем так:

- `useState`
    
- `useEffect`
    
- `loading`
    
- `error`
    

А с `useQuery` можно получить это проще:

```jsx
const { data, isLoading, error } = useQuery({
  queryKey: ["posts"],
  queryFn: fetchPosts,
});
```

---

## Что это значит

- `data` → данные
    
- `isLoading` → идёт загрузка
    
- `error` → ошибка
    
- `queryKey` → имя запроса
    
- `queryFn` → функция, которая делает запрос
    

---

# 20. А как быть с POST / PUT / PATCH / DELETE в React?

Для этого обычно используют **`useMutation`**.

---

## Простое объяснение

- **`useQuery`** → когда нужно **получить** данные (`GET`)
    
- **`useMutation`** → когда нужно **изменить** данные (`POST`, `PUT`, `PATCH`, `DELETE`)
    

---

# 21. Очень важная мысль

Вот лучшая формулировка:

> **Axios** — это инструмент, который отправляет HTTP-запрос.  
> **useQuery** и **useMutation** — это удобные React-хуки, которые помогают правильно и удобно использовать эти запросы в компонентах.

---

# 22. Мини-пример useQuery (без глубокого разбора, как тизер второго урока)

```jsx
import axios from "axios";
import { useQuery } from "@tanstack/react-query";

function Posts() {
  const fetchPosts = async () => {
    const response = await axios.get("https://jsonplaceholder.typicode.com/posts");
    return response.data;
  };

  const { data, isLoading, error } = useQuery({
    queryKey: ["posts"],
    queryFn: fetchPosts,
  });

  if (isLoading) return <h2>Загрузка...</h2>;
  if (error) return <h2>Ошибка</h2>;

  return (
    <div>
      {data.slice(0, 5).map((post) => (
        <p key={post.id}>{post.title}</p>
      ))}
    </div>
  );
}

export default Posts;
```
